# بوت الـ Gateway (الأمر النصي `$استقالة`)

أوامر البادئة (Prefix) لا يمكن استقبالها عبر Interactions Endpoint، لأنها تحتاج اتصال Discord Gateway
دائم. لذلك هذا المجلد يحتوي بوت Node.js صغيرًا تشغّله على استضافتك (Railway / Render / VPS / أي جهاز يعمل 24/7).

## ماذا يفعل؟

- يستمع لرسائل السيرفر، وعند كتابة `$استقالة` أو `$استقاله` (ومع أو بدون مسافة بعد `$`) ينشر **لوحة الاستقالة نفسها** مع زر «استقالة».
- يجلب شكل اللوحة (العنوان/الوصف/اللون/الصور/اسم الزر) من تطبيق Lovable عبر
  `GET /api/public/discord/panel?guild_id=...`، فيبقى التخصيص من داخل ديسكورد كما هو.
- الضغط على الزر، والـ Modal، وأزرار القبول/الرفض كلها تُعالَج في تطبيق Lovable عبر Interactions Endpoint —
  لا حاجة لأي منطق إضافي هنا.

## التشغيل

1. حمّل مجلد `gateway-bot` إلى استضافتك.
2. فعّل **MESSAGE CONTENT INTENT** في Developer Portal → Bot → Privileged Gateway Intents (إلزامي).
3. اضبط متغيّري البيئة (لا تكتب التوكن داخل الكود أبدًا):

```bash
DISCORD_BOT_TOKEN=توكن_البوت
APP_URL=https://guild-leave-manager.lovable.app
```

4. ثبّت وشغّل:

```bash
npm install
npm start
```

الناتج المتوقع: `تم تسجيل الدخول باسم ... — الأمر النصي: $استقالة — الإصدار 2.0.0` ثم `البوت جاهز لاستقبال رسائل السيرفرات.` إذا لم يظهر الإصدار 2.0.0 فالاستضافة ما زالت تشغّل ملفات قديمة.

## ملاحظات

- التوكن هو نفسه المستخدم في تطبيق Lovable (`DISCORD_BOT_TOKEN`)، ويُستخدم أيضًا للمصادقة على مسار اللوحة.
- شغّل نسخة واحدة فقط من البوت لتفادي نشر اللوحة مرتين.
- يجب تنفيذ `/اعداد-الاستقالة` في السيرفر مرة واحدة قبل استخدام الأمر النصي.
- يقبل البوت `$استقالة` و`$استقاله` و`$ استقالة` وكذلك البادئة `!`.
- بعد تحديث الملفات على الاستضافة يجب تنفيذ `npm install` ثم **إعادة تشغيل/إعادة نشر الخدمة**؛ تحديث ملفات هذا المشروع لا يحدّث الاستضافة الخارجية تلقائيًا.
- عند وصول الأمر يظهر في السجل `تم استلام أمر الاستقالة...`. إذا لم يظهر، ففعّل **MESSAGE CONTENT INTENT** وتأكد أن للبوت صلاحية **View Channel** و **Read Message History** في القناة.
